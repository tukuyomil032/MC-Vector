# MC-Vector Native (SwiftUI)

The macOS-only Native edition of MC-Vector. The UI is written entirely in SwiftUI; all server, file, backup, Java, plugin and Ngrok logic comes from the same Rust core as the Tauri edition (`crates/mcvector-core`), exposed to Swift through UniFFI (`crates/mcvector-ffi`).

> Status: early. The app starts, takes the shared data lock, and lists registered servers. Other screens are being ported.

## Relationship with the Tauri edition

- Both editions read and write the **same data** (`~/Library/Application Support/com.tukuyomi032.mcvector`).
- Only **one edition can run at a time**. The second one shows a dialog (bring the running one to the front, or quit) and exits without touching any data.
- Debug builds of both editions use `com.tukuyomi032.mcvector.debug` instead, so development never touches your real servers.

## Requirements

- macOS 15 or later
- Xcode 26 or the matching Command Line Tools (Swift 6)
- Rust (stable) via rustup
- For universal (Intel + Apple silicon) builds: `rustup target add x86_64-apple-darwin aarch64-apple-darwin`

## Scripts

All three scripts work from any directory.

| Script | What it does | Options |
|---|---|---|
| `native/build.sh` | Builds the Rust core, regenerates the Swift bindings, builds the Swift app and assembles `MC-Vector Native.app` (ad-hoc signed) | `--release`, `--universal`, `--clean`, `--verbose` |
| `native/run.sh` | Builds if needed, then launches the app in the foreground with its logs in the terminal | `--release`, `--no-build` |
| `native/test.sh` | Runs the Rust core tests, the Swift tests and the bindings drift check, then prints a summary | `--rust-only`, `--swift-only`, `--check-bindings`, `--filter <pattern>` |

Logs use symbols and colors; set `NO_COLOR=1` (or pipe the output) for plain text.

## Where build output goes

Everything — Cargo output, SwiftPM build and cache, temp files, the `.app` — goes to `native/.build/`. Nothing is written to `~/Library/Developer/Xcode/DerivedData`, `~/Library/Caches`, or `/tmp`. The scripts refuse to write outside `native/.build`. Delete that folder (or run `native/build.sh --clean`) to start from scratch.

Do not build with plain `swift build` or Xcode: the Swift package links the Rust static library that `build.sh` produces.

## Generated bindings

`native/Sources/MCVectorCore/Generated/` (Swift) and `native/Sources/MCVectorFFI/MCVectorFFI.h` (C header) are generated by UniFFI and **committed**, so API changes in the Rust core show up in pull requests. `native/Sources/MCVectorFFI/module.modulemap` is hand-written.

When you change the public API in `crates/mcvector-ffi`, run `native/build.sh` and commit the regenerated files together with the Rust change. `native/test.sh --check-bindings` (also run in CI) fails if they are out of date.

## Layout

```
native/
├─ Package.swift
├─ build.sh  run.sh  test.sh
├─ scripts/lib/       shared shell helpers (logging, bindings)
├─ Resources/         Info.plist template, en/ja Localizable.strings
├─ Sources/
│  ├─ MCVector/       SwiftUI app
│  ├─ MCVectorCore/   typed Swift API over the Rust core (+ Generated/)
│  └─ MCVectorFFI/    C header and module map for the Rust library
└─ Tests/MCVectorTests/
```
