# MC-Vector Native (SwiftUI)

The macOS-only Native edition of MC-Vector. The UI is written entirely in SwiftUI; all server, file, backup, Java, plugin and Ngrok logic comes from the same Rust core as the Tauri edition (`crates/mcvector-core`), exposed to Swift through UniFFI (`crates/mcvector-ffi`).

> Status: early. The app starts, takes the shared data lock, and lists registered servers. Other screens are being ported.

## Relationship with the Tauri edition

- Both editions read and write the **same data** (`~/Library/Application Support/com.tukuyomi032.mcvector`).
- Only **one edition can run at a time**. The second one shows a dialog (bring the running one to the front, or quit) and exits without touching any data.
- Debug builds of both editions use `com.tukuyomi032.mcvector.debug` instead, so development never touches your real servers.

## Requirements

- macOS 15 or later
- Xcode 26 or the matching Command Line Tools (Swift 6)
- Rust (stable) via rustup
- For universal (Intel + Apple silicon) builds: `rustup target add x86_64-apple-darwin aarch64-apple-darwin`

## Scripts

All three scripts work from any directory.

| Script | What it does | Options |
|---|---|---|
| `native/build.sh` | Builds the Rust core, regenerates the Swift bindings, builds the Swift app and assembles `MC-Vector Native.app` (signed as described in [Signing debug builds](#signing-debug-builds)) | `--release`, `--universal`, `--clean`, `--verbose` |
| `native/run.sh` | Builds if needed, then launches the app in the foreground with its logs in the terminal | `--release`, `--no-build` |
| `native/test.sh` | Runs the Rust core tests, the Swift tests, the bindings drift check and the strings drift check, then prints a summary | `--rust-only`, `--swift-only`, `--check-bindings`, `--check-strings`, `--filter <pattern>` |

Logs use symbols and colors; set `NO_COLOR=1` (or pipe the output) for plain text.

## Where build output goes

Everything — Cargo output, SwiftPM build and cache, temp files, the `.app` — goes to `native/.build/`. Nothing is written to `~/Library/Developer/Xcode/DerivedData`, `~/Library/Caches`, or `/tmp`. The scripts refuse to write outside `native/.build`. Delete that folder (or run `native/build.sh --clean`) to start from scratch.

Do not build with plain `swift build` or Xcode: the Swift package links the Rust static library that `build.sh` produces.

## Signing debug builds

macOS remembers privacy grants (Accessibility, Documents, …) by the app's code signature. An ad-hoc signature changes with every build, so each build looks like a new app and loses its grants. `build.sh` therefore signs with, in order:

1. `MCVECTOR_SIGN_IDENTITY` when set (`-` forces an ad-hoc signature);
2. ad-hoc for `--release` builds, since the local certificate means nothing on other Macs;
3. a code-signing certificate named `MC-Vector Dev` when the keychain has one;
4. otherwise ad-hoc, with a warning (CI takes this path).

Create the certificate once per machine (free, about a minute): Keychain Access › Keychain Access menu › Certificate Assistant › Create a Certificate… — name `MC-Vector Dev`, identity type *Self-Signed Root*, certificate type *Code Signing*, tick *Let me override defaults* and set the validity to 3650 days; keep the other defaults and store it in the login keychain. `security find-identity -p codesigning` should list it (marked not trusted, which is fine for local signing). On the first signed build, allow `codesign` to use the key with *Always Allow*.

## Generated bindings

`native/Sources/MCVectorCore/Generated/` (Swift) and `native/Sources/MCVectorFFI/MCVectorFFI.h` (C header) are generated by UniFFI and **committed**, so API changes in the Rust core show up in pull requests. `native/Sources/MCVectorFFI/module.modulemap` is hand-written.

When you change the public API in `crates/mcvector-ffi`, run `native/build.sh` and commit the regenerated files together with the Rust change. `native/test.sh --check-bindings` (also run in CI) fails if they are out of date.

## Strings

The texts come from two sources, and `native/Resources/Localizable.xcstrings` (a String Catalog) holds both:

- The React dictionaries `src/i18n/locales/en.ts` and `ja.ts`. They are the source of truth for every text the Native edition shares with the React UI.
- `native/Resources/native-strings.json`, for texts only the Native edition uses. Each key has `en` and `ja` values, and its keys must not exist in the React dictionaries.

After changing either source, regenerate the catalog and commit it:

```sh
bun native/scripts/sync-strings.ts
```

The output is deterministic. `native/test.sh --check-strings` fails while the committed catalog is out of date. `build.sh` compiles the catalog with `xcstringstool` into `en.lproj` and `ja.lproj` inside the app bundle.

In Swift, look texts up with `L10n.t("react.key", ["name": value])`. React's `{name}` placeholders are kept and filled by name. The language follows `locale` in the shared `config.json`, otherwise the system language.

## UI approach

The [General Settings API](GENERAL_SETTINGS.md) documents shared defaults,
validation, restart behavior, and synchronization with `server.properties`.

The Native edition keeps the Tauri edition's screens and features, but it is a Mac app: it follows Apple's Human Interface Guidelines and uses the standard SwiftUI and macOS components (sidebar list, system sidebar toggle, toolbar items, toolbar search, `Form`, `Table`, sheets, alerts, context menus, `ContentUnavailableView`). Do not recreate web widgets or the web color theme.

## Screenshots of the app

`native/scripts/capture.sh` launches the debug app in a known state and saves a screenshot of its window, for reviews and for checking features against the React UI reference:

```sh
native/scripts/capture.sh --fixture groups --locale ja SHELL-ROOT TOAST-stack-3
```

- States are defined in `Sources/MCVector/Capture/CaptureState.swift` (debug builds only).
- `--fixture` picks the server data in `scripts/fixtures/<name>/` (`e2e`, `groups`, or `empty`); each launch gets a fresh copy in `~/Library/Caches/com.tukuyomi032.mcvector.capture/fixtures/`, so your real data is never touched.
- Output: `native/.build/captures/<locale>/<ID>.png`. The terminal needs the Screen Recording permission.
- States that open a context menu (`*-context-menu`) post a right click, which needs the Accessibility permission for "MC-Vector Native". Without it the capture stops at once and opens that settings pane. The grant survives rebuilds only with a stable signature (see [Signing debug builds](#signing-debug-builds)).

## E2E

Run `native/scripts/e2e.sh --locale ja` to build and run the Native pass/fail suite.
Use `--no-build` after an existing debug build, or pass state IDs to run a subset:

```sh
native/scripts/e2e.sh --locale ja --no-build VERIFY-files VERIFY-editor
native/scripts/e2e.sh --locale en --all
```

The default suite runs `E2E-relaunch`, `E2E-navigate`, and every `VERIFY-*`
state except `VERIFY-real-*`. `--all` includes the real Paper states, which
require network access and a compatible Java installation. Relaunch checks
window restoration across two direct executable launches and graceful quits;
navigation checks routes and Settings; verification states emit explicit
success/failure checks for server, file, and editor operations.

Each state gets fresh fixture data. The runner requires readiness, a living
process for two seconds after readiness, and at least one successful check.
Any failed check, unknown state, readiness timeout (30 seconds, or 300 seconds
for real Paper), or early exit fails the state. A table reports each result,
elapsed seconds, and the first failure. Exit status is 1 when any state fails,
or 2 for invalid usage or when another non-capture MCVector process is running.
The runner refuses to proceed if it cannot inspect the process list.

Logs and fixture data use the same runtime directory as capture:
`~/Library/Caches/com.tukuyomi032.mcvector.capture`, overridable with
`MCVECTOR_CAPTURE_RUN_DIR=<absolute path>`. Build output stays in `native/.build`.
The runner stops its app and fixture servers after each state. Quit any normal
MCVector session before running it.

## Layout

```
native/
├─ Package.swift
├─ build.sh  run.sh  test.sh
├─ scripts/
│  ├─ lib/            shared shell helpers (logging, bindings)
│  ├─ sync-strings.ts generates Resources/Localizable.xcstrings
│  └─ sync-versions.ts generates Resources/minecraft-versions.json
├─ Resources/         Info.plist template, Localizable.xcstrings, native-strings.json
├─ Sources/
│  ├─ MCVector/       SwiftUI app
│  ├─ MCVectorCore/   typed Swift API over the Rust core (+ Generated/)
│  └─ MCVectorFFI/    C header and module map for the Rust library
└─ Tests/MCVectorTests/
```
