# Java source disposition shard schema

Each `part-*.json` file is a deterministic partition of AST declarations that are not yet present in `spec/map/coverage/source-symbol-dispositions.json`. `part-a.json` selects the first 8,832 missing `symbolId` values after bytewise ascending sort and records its half-open range in the header.

Every entry preserves `symbolId`, `sourcePath`, `signature`, `sourceSpan`, `sourceGitBlobSha1`, and `sourceContentSha256` from the pinned AST/source-file inventory. `classification` uses the validator enum `required`, `boundary_adapter`, or `excluded`; `boundary_adapter` is the contract name for adapter-only scope. Every entry includes `rationale` and `dependencyEdgeIds`. Required and boundary-adapter entries also include `rustDestination`, `ownerPhaseId`, `ownerPhaseDocument`, `fixturePlanIds`, `referencePlanIds`, `focusedTestPlanIds`, and `evidencePlanIds`. Excluded entries include `exclusionEvidenceIds` and do not claim a Rust implementation destination.

Planned fixture/reference/test/evidence keys are `FIX-SYMBOL-<sha256(symbolId)>`, `REF-SYMBOL-<sha256(symbolId)>`, `TEST-SYMBOL-<sha256(symbolId)>`, and `EVID-SYMBOL-<sha256(symbolId)>`. They designate future evidence work; they do not claim that fixtures, captures, tests, or implementation evidence already exist. `implementationStatus` remains `unverified`. Where reflection, dynamic configuration, unresolved candidate edges, or an incomplete root path prevents a final scope decision, the row records the exact open fact, reason, and available reference IDs in `unresolvedFacts` and assigns the resolution work to P-000.

`sourceEvidence` records the pinned source excerpt, outgoing and incoming candidate edges, source caller identities, renderer-root path edges when resolved, string-literal review candidates, unmatched semantic-reference IDs/counts, and adapter type hierarchy where applicable. String-literal rows remain candidates until their call context proves dynamic lookup. Exclusions carry an `exclusionEvidence` record keyed by `exclusionEvidenceIds`, with the pinned declaration span and relevant incoming/outgoing edge IDs.

Rationales are declaration-specific and cite the pinned source span plus source-call, registration, hierarchy, or dependency-edge evidence. Package/path membership alone is not sufficient evidence for a disposition. Open P-000 rows are planned resolution work, not a claim that their final scope or implementation has been verified.
