The **Backups** tab lets you snapshot your server and restore it to any saved state.

Backup and archive destinations are managed by the Rust backend. The UI identifies a server and
relative backup entry instead of providing arbitrary source or destination paths. Archive entries
are checked for traversal, links, excessive nesting, entry count, expanded size, and compression
ratio before extraction.

## What Gets Backed Up

Every backup is a full snapshot of the entire server directory (all worlds, configs, and plugins). MC-Vector does not offer partial or differential backups, so there is no per-folder selection. Take a backup before major changes such as version upgrades or large plugin installs.

## Backup Storage Location

| Platform | Path                                                              |
| -------- | ----------------------------------------------------------------- |
| macOS    | `~/Library/Application Support/MC-Vector/servers/<name>/backups/` |
| Windows  | `%APPDATA%\MC-Vector\servers\<name>\backups\`                     |
| Linux    | `~/.local/share/MC-Vector/servers/<name>/backups/`                |

## Creating a Backup

1. Navigate to the **Backups** tab.
2. Click **"Create Backup"**.
3. Choose:
   - **Compression** — level 1 (low) to 9 (high)
   - **Name** — custom ZIP file name (optional)
4. Optionally add a **tag** and **notes** for identification.
5. Click **"Create"** — progress is shown in real-time.

If the server is running, MC-Vector asks before stopping it for a manual backup. After confirmation, it waits for the server process to exit, creates the backup, and attempts to restore the server to its previous running state. If the server cannot be stopped, no backup is created. Minecraft-generated `session.lock` files are automatically excluded from backups.

## Restoring a Backup

:::caution[Stop the server first]
Always stop the server before restoring a backup. Restoring while the server is running can cause world corruption.
:::

1. Select a backup from the list.
2. Click **"Restore"**.
3. Confirm — the server directory is overwritten with the backup contents.
4. Start the server.

## Deleting Backups

1. Select a backup from the list.
2. Click **"Delete"** and confirm.

## Automatic Backups

Automatic backups can be configured in [General Settings](/guide/configuration/general-settings#automatic-backups). Options include:

- **Interval** — every N minutes
- **Daily** — once per day at a specific time (HH:MM)
- **Weekly** — once per week on a specific day and time

A **retention policy** controls how many backups are kept automatically: by count limit or by age (days).
